# AGENT.md

Guidance for AI agents (and new contributors) working in this repository.

## What this is

**Tina2 Print** — an unofficial, open-source Android client for the **WEEDO Tina2S**
(and compatible WEEDO) 3D printer. It talks to the printer's **local Wi-Fi API**
directly: no cloud, no PC, no vendor app.

- Package: `com.retallack.tina2print` · App label: "Tina2 Print"
- Language: Java (Android), `minSdk 21`, `targetSdk 34`
- License: MIT (© 2026 Mark Retallack)
- Not affiliated with WEEDO / Entina. "Tina2" / "WEEDO" are their trademarks.

The printer exposes an **OctoPrint-compatible REST API over plain HTTP on port 80,
with no authentication**. The app talks to that API directly. The protocol was
reverse-engineered statically from the vendor *Poloprint Local* app
(`com.weedo3d.pplocal`) — see [`docs/LAN-PROTOCOL.md`](docs/LAN-PROTOCOL.md).

## Three tabs

1. **Print** — set / auto-discover the printer IP (scans the local `/24`), upload a
   `.gcode` file, optionally start printing; job control (Start / Pause / Cancel).
2. **Slice** — offline slicing on the phone. Load an STL, slice with the embedded
   **Kiri:Moto** engine inside a `WebView`, tune layer height / infill / walls /
   temps / raft / supports, then send the G-code to the printer.
3. **Status** — live readout; polls `/api/version`, `/api/printer` and `/api/job`
   every 2 s **only while the tab is visible**.

## Architecture

- **`src/com/retallack/tina2print/MainActivity.java`** (~890 LOC) — single Activity
  (no fragments). Builds all three tabs programmatically (no XML layouts), holds the
  printer HTTP client (`HttpURLConnection`), the LAN `/24` scan, and a `WebView`
  `JavascriptInterface` bridge (`SliceBridge`) for the slicer.
- **`src/com/retallack/tina2print/LocalServer.java`** (~190 LOC) — a tiny loopback
  HTTP server (`127.0.0.1`, ephemeral port) that serves the slicer page and assets to
  the `WebView`. It:
  - serves `assets/` (default `slice.html`), streams the loaded STL at `/stl`,
    receives finished G-code via `POST /gcode`;
  - adds the `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` headers
    the slicer needs for `SharedArrayBuffer`. Serving over `http://127.0.0.1` (not
    `file://`) also lets the page stream large STLs efficiently.
- **`assets/slice.html`** (~480 LOC) — the slicer UI plus the **Tina2S device/process
  profile** (100×100×100 mm bed, 0.4 mm nozzle, 1.75 mm filament, PLA; based on
  Kiri:Moto's built-in `Tina2.Basic.json`). Contains the start (`gcodePre`) and end
  (`gcodePost`) G-code blocks and the raft/support panels.
- **`assets/`** also holds the **generated** Kiri:Moto runtime: `lib/kiri/run/`
  (`engine.js`, `worker.js`, `minion.js`, `manifold.wasm`), `lib/kiri/wasm/`, and
  `wasm/` (`kiri-geo.wasm`, `kiri-sla.wasm`, `manifold.wasm`). All are **built from
  source**, committed for convenience, and regenerated by `tools/build-slicer.sh`.
- **`AndroidManifest.xml`** — declares `INTERNET`, `ACCESS_NETWORK_STATE`,
  `ACCESS_WIFI_STATE`; `usesCleartextTraffic="true"`; a single exported `.MainActivity`.

No Gradle, no XML resources, no third-party Java libraries — just the Android SDK.

## Building the app

Built **without Gradle**, using the Android SDK command-line tools directly
(`aapt2`, `javac`, `d8`, `zipalign`, `apksigner`).

```bash
export ANDROID_SDK_ROOT=/path/to/android-sdk
./build.sh          # -> Tina2Print.apk (signed with the debug keystore by default)
```

- Expects `build-tools/35.0.0` and `platforms/android-34`.
- Creates `~/.android/debug.keystore` if missing.
- Optional env override for release signing: `KEYSTORE_PATH`, `KEYSTORE_PASSWORD`,
  `KEY_ALIAS`, `KEY_PASSWORD`.
- Optional version stamping: `VERSION_CODE`, `VERSION_NAME` (passed to `aapt2 link`).
- `build.sh` uses `set -euo pipefail`; it produces the final `Tina2Print.apk` in the
  repo root (and intermediate artifacts under `build/`, which is gitignored).

Install: `adb install -r Tina2Print.apk`

## Building the slicer (Kiri:Moto) from source

Every Kiri:Moto asset in the APK is compiled from source — nothing is copied from a
prebuilt download. Source is vendored as a git submodule at `thirdparty/grid-apps`
(pinned commit).

```bash
git submodule update --init --recursive   # fetch vendored slicer source
./tools/build-slicer.sh                    # rebuild assets/lib/kiri + assets/wasm
```

Requirements: `node`/`npm` and the **Emscripten SDK** (`emcc`/`em++`) on `PATH`.
The script: applies local patches (below), `npm install`, pins `manifold-3d@3.3.2`
for a reproducible `manifold.wasm`, builds derived JS bundles (three, jszip, quickjs,
planegcs), bundles `engine.js`/`worker.js`/`minion.js` with esbuild, compiles the WASM
geometry modules, and copies everything into `assets/`.

### Local patches to the vendored slicer

`thirdparty/grid-apps` is an unmodified upstream submodule. Local changes live as
patches in `tools/patches/` and are applied (once) by `tools/build-slicer.sh`, so a
fresh `git submodule update` can't silently drop them. **Any slicer change must follow
this shape**: a small hunk in the submodule, exported as a patch here.

- `0001-raft-layer-settings.patch` — `src/kiri/mode/fdm/work/prepare.js`: the four
  hardcoded raft layers read height / line spacing / speed / flow from `outputRaft*`
  process settings, each falling back to the original constant. Drives the **Raft
  tuning** panel. Untouched config yields byte-identical G-code.
- `0002-cap-minion-pool.patch` — `src/kiri/run/worker.js`: caps the minion pool at 2
  workers instead of scaling with `hardwareConcurrency`.

### Slicer gotchas (don't regress these)

- **The minion pool must run.** Kiri:Moto queues per-layer boolean diffs (and *all*
  support generation) to a minion worker; a queued job with no minion never resolves.
  The app always starts the pool (`setController({ threaded: true })`) and ships
  `assets/lib/kiri/run/minion.js`. The 60 s stall watchdog and **Reset slicer** button
  are the backstop. ("Stuck at layer deltas" ~70 % was this, not geometry.)
- **End-of-file terminator matters.** Every export appends `M82` + `;End of Gcode`
  after a trailing newline; the Tina2S firmware only runs the end block then.
- **Start/end G-code follows Cura's proven Tina2 sequence** (nozzle preheats to 150 °C
  before homing/levelling, `G29` on a hot bed, 10 s heat-soak, prime line; end block
  parks and turns off heaters). Don't casually change it.

## How printing works on this printer

No "play" button — uploading does not start a print.

1. `POST /api/files/local` (multipart) uploads the `.gcode`; the firmware writes it to
   the SD card and renames it to **8.3** (`slice.gcode` → `SLICE~1.GCO`). Must use a
   fixed `Content-Length` — the ESP32 does not accept chunked encoding.
2. `POST /api/files/sdcard/<8.3 name>` `{"command":"select","print":true}` — **this
   actually starts the print.** Note the `sdcard` location, not `local` (`local`
   404s on the Tina2S). The app retries `select` until the job reports `Printing`.

Full recovered API surface, response shapes, and live captures are in
[`docs/LAN-PROTOCOL.md`](docs/LAN-PROTOCOL.md).

## Self-update (GitHub Releases → PackageInstaller)

The app updates itself with no Play Store / F-Droid. On `onCreate` it calls
`Updater.checkOnStartup(this)` (non-blocking):

- **`Updater.java`** — on a background thread, fetches
  `https://api.github.com/repos/mretallack/Tina2SLocal/releases/latest` (User-Agent +
  `application/vnd.github+json`), picks the first `.apk` asset, and compares
  `tag_name` (minus a leading `v`) against the installed `versionName` with a numeric
  segment compare (`isNewer`). If newer and not skipped, an `AlertDialog` offers
  **Update / Later / Skip this version** (skip is remembered per-version in the
  `tina2print` prefs). On confirm it downloads the APK to `cacheDir` and installs it.
- **Install path** — a `PackageInstaller.Session` (`MODE_FULL_INSTALL`), *not* an
  `ACTION_VIEW` intent on a file URI. That means **no `FileProvider` and no `res/xml`
  is needed** — important because this project has no `res/` and `build.sh` does not
  compile resources. On API 26+ it checks `canRequestPackageInstalls()` and, if false,
  sends the user to `ACTION_MANAGE_UNKNOWN_APP_SOURCES` and stops.
- **`UpdateResultReceiver.java`** — manifest-declared `BroadcastReceiver` that handles
  the session's status: `STATUS_PENDING_USER_ACTION` (launches the confirm intent the
  system hands back), `STATUS_SUCCESS`, or failure (toasts the status message).

Manifest additions: `REQUEST_INSTALL_PACKAGES`, the `.UpdateResultReceiver` receiver,
and `versionCode`/`versionName` defaults (`1` / `0.0.0`) so unstamped local builds
sort below any release and would offer the latest — CI overrides them via `build.sh`
env (`VERSION_CODE`/`VERSION_NAME`, where `VERSION_NAME` is the tag).

Constraints to keep in mind:

- **Same signing key is mandatory.** Android rejects an update signed with a different
  key. Self-update therefore only works for **release-signed** builds; the default
  `./build.sh` is debug-signed. Publish releases with the release keystore.
- **The release must carry the APK asset** — the `release` CI job attaches
  `Tina2Print.apk` via `softprops/action-gh-release`, which is what the updater
  downloads. `releases/latest` excludes drafts/prereleases.
- GitHub's unauthenticated API is rate-limited (~60 req/h/IP); the check is once per
  launch and fails silently, which is fine.

## CI — `.github/workflows/android-ci.yml` ("Android CI")

Triggers: push to `main`, push of tags `v*`, PRs to `main`, published releases, and
manual dispatch. `permissions: contents: read`; concurrency cancels superseded runs.

Two jobs:

**`build` — Build APK** (on every trigger)
1. `actions/checkout@v4`
2. JDK 17 (temurin)
3. `android-actions/setup-android@v3`, installing only `platform-tools` (the default
   `tools` package was removed from the SDK — this is a deliberate fix).
4. `sdkmanager --install` `platforms;android-34` and `build-tools;35.0.0`, then accept
   licenses.
5. Decode `secrets.KEYSTORE_BASE64` into `release.keystore` (only if the secret is set).
6. Run `./build.sh`, passing `KEYSTORE_*` / `KEY_*` from secrets when available (falls
   back to the debug keystore otherwise).
7. Upload the APK as the `Tina2Print-apk` artifact (`if-no-files-found: error`).

**`release` — Attach APK to release** (only on a published release or a `v*` tag)
- Runs after `build` (`needs: build`) with `contents: write`.
- Repeats the checkout/JDK/SDK setup, then builds with `VERSION_NAME=${{ github.ref_name }}`
  and `VERSION_CODE=${{ github.run_number }}`, and attaches `Tina2Print.apk` to the
  GitHub Release via `softprops/action-gh-release@v2`.

Notes for agents:
- CI builds only the **app**, not the slicer. It uses the **committed** Kiri:Moto
  assets; it does not fetch the submodule or run `tools/build-slicer.sh`. If you
  regenerate slicer assets, commit them or CI ships stale binaries.
- Release signing requires the `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`,
  `KEY_PASSWORD` secrets; without them the artifact is debug-signed.

## Conventions & gotchas for agents

- **Match the existing style.** Java is hand-written, dependency-free, one Activity;
  keep it that way. Comments explain *why* (protocol quirks, firmware behaviour),
  not *what*.
- **Slicer changes go through `tools/patches/`**, never as loose edits to the
  submodule. Re-run `tools/build-slicer.sh` and commit regenerated assets.
- **Don't break the print flow:** `sdcard` (not `local`) for select/print, fixed
  `Content-Length` on upload, end-of-file `M82` + `;End of Gcode`, minion pool on.
- **Protocol is the source of truth** in `docs/LAN-PROTOCOL.md`; update it if you
  learn more from the printer.
- Keep the README up to date for user-facing changes; keep this file up to date for
  build/CI/architecture changes.
